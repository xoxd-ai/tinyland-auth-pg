# tinyland-auth-pg v0.2.0 Implementation Plan

> **Historical plan:** The publication commands and npm identities below record
> the 0.2.0 plan and are not current release authority. Current first-party
> consumption is the `tummycrypt_tinyland_auth_pg` Bzlmod module. npmjs
> publication is disabled; the only configured compatibility artifact is a
> publish-time rewrite to GitHub Packages identity
> `@tinyland-inc/tinyland-auth-pg`. See the repository README and publish
> workflow for the current contract.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@tummycrypt/tinyland-auth-pg@0.2.0` that (a) accepts a pre-built drizzle client via DI instead of constructing neon-http internally, and (b) enforces tenant isolation via explicit `tenantId` on every adapter method (Pattern B) backed by `tenant_id uuid NOT NULL` on every row-bearing table.

**Architecture:** Backward-compatible factory — `createPgStorageAdapter({db})` for DI path (postgres.js, node-postgres, neon-http, anything returning a `drizzle-orm` client), `createPgStorageAdapter({connectionString})` for legacy neon-http path. Every adapter method signature changes to accept `tenantId` as first param; every INSERT sets `tenant_id`; every SELECT/UPDATE/DELETE filters by `tenant_id`. Row mappers remain pure.

**Tech Stack:** TypeScript 5.9, drizzle-orm 0.39.3, vitest 4, pnpm 9.15.9, Bazel (aspect_rules_js/ts), Nix flake. Test infra adds `@testcontainers/postgresql` for cross-driver smoke tests.

**Blast radius:** This is a breaking change for 0.1.x callers. Only known caller is MassageIthaca (pinned `^0.1.1` today). Publishing as 0.2.0 per semver-pre-1.0 convention for breaking minor.

- [ ] **Step 5: Add tenantId param to every method signature**

Walk every method in `PgStorageAdapter`. Pattern B: `tenantId: string` is the first parameter (validated as uuid at runtime is overkill — trust the caller). Add `eq(schema.TABLE.tenantId, tenantId)` inside every `.where(and(...))` clause. For INSERTs, set `tenant_id: tenantId` on the row before insertion.

Example transformation for `getUser`:

```typescript
// Before
async getUser(id: string): Promise<AdminUser | null> {
  const rows = await this.db.select().from(schema.users).where(eq(schema.users.id, id)).limit(1);
  return rows[0] ? toAdminUser(rows[0]) : null;
}

// After
async getUser(tenantId: string, id: string): Promise<AdminUser | null> {
  const rows = await this.db
    .select()
    .from(schema.users)
    .where(and(eq(schema.users.tenantId, tenantId), eq(schema.users.id, id)))
    .limit(1);
  return rows[0] ? toAdminUser(rows[0]) : null;
}
```

Example transformation for `createUser`:

```typescript
// Before
async createUser(user: Omit<AdminUser, 'id'>): Promise<AdminUser> {
  const [row] = await this.db.insert(schema.users).values({ ... }).returning();
  return toAdminUser(row);
}

// After
async createUser(
  tenantId: string,
  user: Omit<AdminUser, 'id' | 'tenantId'>,
): Promise<AdminUser> {
  const [row] = await this.db
    .insert(schema.users)
    .values({ ...mapUserToRow(user), tenantId })
    .returning();
  return toAdminUser(row);
}
```

import { describe, it, expect, beforeAll, afterAll } from 'vitest';
import { PostgreSqlContainer, type StartedPostgreSqlContainer } from '@testcontainers/postgresql';
import postgres from 'postgres';
import { drizzle } from 'drizzle-orm/postgres-js';
import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';
import { createPgStorageAdapter } from '../adapter.js';
import * as schema from '../schema.js';

const hasDocker = !!process.env.CI || !!process.env.DOCKER_HOST || process.platform === 'linux';

describe.skipIf(!hasDocker)('postgres.js + tenant isolation smoke', () => {
  let container: StartedPostgreSqlContainer;
  let sql: ReturnType<typeof postgres>;

  const TENANT_A = '11111111-1111-1111-1111-111111111111';
  const TENANT_B = '22222222-2222-2222-2222-222222222222';

  beforeAll(async () => {
    container = await new PostgreSqlContainer('postgres:16-alpine').start();
    sql = postgres(container.getConnectionUri(), { prepare: false, max: 4 });

    const authFiles = readdirSync(authDir).filter(f => f.endsWith('.sql')).sort();
    for (const f of authFiles) {

    await sql?.end({ timeout: 5 });
    await container?.stop();
  });

  it('createUser scopes by tenantId', async () => {
    const db = drizzle(sql, { schema });
    const adapter = createPgStorageAdapter({ db });

    const a = await adapter.createUser(TENANT_A, {
      handle: 'alice',
      email: 'alice@example.com',
      passwordHash: 'hash_a',
      role: 'admin',
      isActive: true,
      needsOnboarding: false,
      onboardingStep: 0,
      totpEnabled: false,
    });
    const b = await adapter.createUser(TENANT_B, {
      handle: 'alice', // SAME handle — would collide in 0.1.x; must succeed here
      email: 'alice@example.com',
      passwordHash: 'hash_b',
      role: 'admin',
      isActive: true,
      needsOnboarding: false,
      onboardingStep: 0,
      totpEnabled: false,
    });

    expect(a.id).not.toBe(b.id);
    expect(a.tenantId).toBe(TENANT_A);
    expect(b.tenantId).toBe(TENANT_B);
  });

    const adapter = createPgStorageAdapter({ db });

    const fromB = await adapter.getUserByHandle(TENANT_B, 'alice');

    expect(fromA?.passwordHash).toBe('hash_a');
    expect(fromB?.passwordHash).toBe('hash_b');

  it('getAllUsers returns only the current tenant', async () => {
    const db = drizzle(sql, { schema });
    const adapter = createPgStorageAdapter({ db });

    const usersA = await adapter.getAllUsers(TENANT_A);
    const usersB = await adapter.getAllUsers(TENANT_B);

    expect(usersA.every(u => u.tenantId === TENANT_A)).toBe(true);
    expect(usersB.every(u => u.tenantId === TENANT_B)).toBe(true);

## [0.2.0] — 2026-04-17

### Breaking Changes

- Every `PgStorageAdapter` method signature now takes `tenantId: string` as first parameter (Pattern B).
- Every row-bearing table now has `tenant_id uuid NOT NULL`. Existing deployments MUST run a migration that seeds `tenant_id` before upgrading.

### Migration Guide (0.1.x → 0.2.0)

1. Add `tenant_id` column to every table (run generated migration).
2. Update every call site: `adapter.getUser(id)` → `adapter.getUser(tenantId, id)`.
3. For INSERTs, drop `tenantId` from the row object — the adapter now sets it from the first param.

## [0.1.1] — 2026-04-06

- First published release.
